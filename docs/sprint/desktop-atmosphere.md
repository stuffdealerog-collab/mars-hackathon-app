**Что меняется, коротко**
1. **Обводки нет.** На горящей лампе на ПК нет ни одной чёрной тени: ни у текста, ни у точек LED. Серого кольца по краю тоже нет. Лампа выглядит так, как владелец утвердил в 23:08. Текст опущен под колбу, контраст ≥ 5,3:1 без ореолов (§3).

4. **Отдел — главный предмет** на Start, Working, Bo‘lim и лендинге: общий корпус и плитки 160 px. В покое в филаментах тлеют угольки (§5).
5. **Лендинг:** в первом экране горит честный образец пекарни с чипом «namuna». Когда владелец набрал ссылку, образец гаснет и взводятся его лампы (§6).

### 1.2 Почему «фулл чёрный»

1. **Свету некуда падать.** На `#000` не видно ни света, ни тени. Карточки `#0d0d10` на `#000` (1,08:1) читаются как вырезы в экране.
2. **Свет заперт в плитках.** В 5 px от края горящего Strateg пиксель снова `(0,0,0)`.
3. **Мазок у хаба.** `StageLight` рисует `wash` — до четырёх эллипсов `hue/.35` на `x = 9%`, ни под одной лампой. На `19`, `20`, `26`, `27` это буро-красный туман без источника.
4. **Хаб — тёмная картонка.** Под стеклом `rgb(18 18 22/.46)` чистый чёрный. На `27` между «Asboblar» и футером 250 px пустого стекла.
5. **Пустоты больше, чем предметов.** На Start и Working узкая колонка 560–720 px, вокруг 60–90% плоской сцены. На образце самый крупный предмет — пустой слот Дизайнера.
6. **Выключенный отдел — пустые клавиши.** Десять плиток `#0d0d10` с серой чёрточкой не похожи на прибор, и включение лампы не читается как событие.

### 1.3 Где сейчас «обводка» (код `main`, PR #20)

- `globals.css:554–556`: `.lamp__result { text-shadow: 0 1px 2px rgb(0 0 0/.55), 0 0 14px rgb(0 0 0/.45) }` — тёмные пятна вокруг слов.
- `globals.css:560–562`: `.lamp__result svg { filter: drop-shadow(0 1px 2px rgb(0 0 0/.55)) drop-shadow(0 0 7px rgb(0 0 0/.45)) }` — чёрное кольцо вокруг каждой точки LED (видно на `40`, увеличено: Analitik «60», Strateg «7»).
- `globals.css:597–601`: `.lamp__state, .lamp__job { text-shadow: 0 1px 8px rgb(0 0 0/.35) }`.
- `globals.css:497–505`: `.lamp__glow::after { box-shadow: …, inset 0 0 0 1px rgb(255 255 255/.08) }` плюс `inset 0 0 0 1px var(--hair)` у самой `.lamp` (`:448`). Свет уходит в `transparent 88%`, и два кольца обводят тёмный низ плитки. Так же у мини-ламп хаба.

**Почему ореолы там стоят.** Результат печатается в самой яркой части свечения: на плитке Bo‘lim высотой 160 px верх LED-цифры стоит на y ≈ 24, а белый там даёт Brend 2,1:1, Analitik 2,5:1, SMM 2,6:1 (модель §3.4). Ореол заклеивал ошибку места, как раньше плашка. Если убрать ореол и оставить место, контраст упадёт. Чинить надо место текста, а не тень.

Ловушка специфичности: `.lamp:not(.lamp--xs) .lamp__glow` — это (0,3,0), `[data-theme=light] .lamp:not(.lamp--xs) .lamp__glow` — (0,4,0). Новые правила ПК должны быть сильнее (§3.3). Плашки `background: rgb(0 0 0/.56)` в `main` уже нет: её убрал PR #19.

### 1.4 Что сохраняем

Вид горящей лампы из PR #20 (`--g-*`, `GLOW_DIM = .15`), её цвета, спектр в порядке конвейера, янтарную LED-вывеску, лайм только для руки владельца, Spektr, Onest, правило «свет = работа». Телефон, `/tg`, Mini App и светлая тема этой ночью не меняются.

## 3. Лампа на ПК без обводки (P0, шаг 1)

### 3.1 Что убираем (только под `.desk`)

- Все чёрные `text-shadow` у `.lamp__result`, `.lamp__title`, `.lamp__state`, `.lamp__job` горящей лампы.
- `filter` с чёрными `drop-shadow` на `.lamp__result svg`. Собственное белое свечение точек (`Led`, `glow` по умолчанию) остаётся.
- Кольцо `inset 0 0 0 1px rgb(255 255 255/.08)` в `.lamp__glow::after`. Губа сверху (`inset 0 1px 0 rgb(255 255 255/.22)`) остаётся.
- Hairline `inset 0 0 0 1px var(--hair)` у горящей плитки. У выключенной своя кромка (§3.5).

Цветной ореол тоже не добавляем: у Brend `deep` почти такой же яркий, как свечение под текстом, и ореол цвета лампы контраста не даёт. Контраст делает место текста.

### 3.2 Геометрия: текст под колбой

- Радиусы свечения на текстовых плитках ПК фиксируются в пикселях — ровно такие, как у утверждённой плитки Bo‘lim высотой 160 px: колба `55% 45px at 50% 0`, свет `120% 125px at 50% -10px`. Тогда яркая зона не растягивается, когда плитка становится выше, и вид остаётся утверждённым.
- `padding-top` тела — 52 px (было 24). Над текстом — только колба и филамент, текст начинается там, где свет уже ушёл в `mid`/`deep`.
- Плитки ПК: `min-height: 160px`, `border-radius: 24px`, имя 15 px. Отдельного размера `lg` нет: ширину даёт сетка (163 px в колонке 880, 117 px на 1024 с полным хабом).
- `Num` остаётся колонкой (LED над подписью): в строку «2/5 rasm» не помещается в 117 px.
- Высота содержимого: 52 + LED 32 + 8 + подпись 13 + 8 + имя 17 + 2 + слово состояния 15 + 14 = 161 px. В Bo‘lim со строкой `job` плитка ≈ 194 px.

Модель: композит `--glass` → `.lamp__spill` (.42) → свечение → колба, вдоль центральной вертикали (там свет ярче всего), белый текст без ореола.

## 4. Комната (P0, шаги 2–3)

### 4.1 Токены ПК

Опора: тёмная тема Material строится на `#121212`, а не на чёрном, и поверхности поднимаются светлотой: чем выше слой, тем он светлее (https://m2.material.io/design/color/dark-theme). У профессиональных инструментов, где сидят часами (Logic, Resolve, Lightroom, Figma), фон — графит, а не чёрный. Холодный сине-чёрный, как у Linear и Raycast, спорит с янтарём, поэтому берём тёплый нейтральный с хромой ≤ 0,006, чтобы не уйти в коричневый.

```css
@media (min-width: 1024px) {
  .desk:not([data-theme="light"]) {
    --stage: #171513;     /* тёплый графит, OKLab L ≈ .20: тёмная комната, не дыра */
    --glass: #1f1c19;     /* карточки, очередь, инспектор: светлее комнаты */
    --glass-2: #27241f;   /* tgpost, поле ссылки */
    --glass-3: #302c27;   /* меню, палитра, выбранное */
    --hair: rgb(255 240 220 / .07);
    --hair-2: rgb(255 240 220 / .13);
    --ink-3: #948f87;     /* старый #85817a на --glass даёт 4,38:1 */
    --led-well: #0d0c0a;  /* окно вывески: самый тёмный предмет, но не #000 */
    /* Алиасы вычислены на :root и наследуются готовыми значениями: переопределяем их тоже. */
    --paper: var(--stage); --card: var(--glass); --tint: var(--glass-2);
    --line: var(--hair); --line-2: var(--hair-2);
  }
  html:has(.desk:not([data-theme="light"])) { background: #171513; }   /* без чёрного при overscroll */
}
```

Контраст на графите: `ink` 16,1:1, `ink-2` 7,3:1, `ink-3` 5,7:1. На `--glass` `ink-3` — 5,3:1, на `--glass-2` — 4,8:1.

Запасное значение: если в контрольной точке A (§9.1) графит на реальном ноутбуке читается серым, `--stage` → `#121110`, `--glass` → `#1b1916`. Остальное не меняется.

### 4.2 Что убрано из редакции 1

Дежурный свет сверху (это прожектор героя из клонов Linear, без видимого источника), виньетка, фиксированный слой `.room`, A/B-кроссфейды, `room-on`, усреднение по колонкам в OKLab, `--veil`, зерно (перенесено в P1), палитра клиента (P2: без дежурного света ей нечего красить). Свет в комнате даёт только то, что светит само: лампы, картинка, вывеска.

### 4.3 Свет ламп на комнату (`PanelStage`)

Опора: Philips Ambilight, где свет за экраном в каждой зоне повторяет цвет её края и лучше всего работает в тёмной комнате со стеной (https://en.wikipedia.org/wiki/Ambilight), и «гребешки» настенных светильников, где каждый источник рисует на стене своё пятно. Свет правдив: каждое пятно стоит у своей лампы. Сплошной радуги и усреднения нет.

`Panel` получает `housing?: boolean`. С ним разметка такая:

```tsx
<div className="panel-stage" data-armed={armed || undefined}>
  {LAMP_ORDER.map((r, i) => (
    <span
      key={r} aria-hidden className="room-light"
      data-row={i < 5 ? "top" : "bottom"}
      data-on={st === "warming" ? "warm" : st === "on" || st === "you" ? "on" : undefined}
      data-soon={lamps.soon.has(r) || undefined}
      style={{ "--k": i % 5, background: "var(--room)", ...VARS[r] } as React.CSSProperties}
    />
  ))}
  <div className="panel-housing">
    <ul ref={ref} …>{/* плитки, ref остаётся на ul: Spektr читает panel.children */}</ul>
  </div>
  {children /* SpectrumIntro в Working: его host — .panel-stage */}
</div>
```

```css
.panel-stage { position: relative; isolation: isolate; }
.panel-housing {
  padding: 12px; border-radius: 34px; background: #12110f;   /* утопленная панель, без тени окклюзии */
  box-shadow: inset 0 1px 0 rgb(255 255 255 / .05), inset 0 0 0 1px rgb(255 255 255 / .035);
}
.room-light {
  position: absolute; z-index: -1; pointer-events: none;
  width: 26%; left: calc((var(--k) + .5) * 20% - 13%);       /* пятно чуть шире колонки, по центру лампы */
  mix-blend-mode: plus-lighter;                              /* соседние пятна складываются, как свет */
  opacity: 0; transition: opacity var(--t-off) var(--ease-in);
}
.room-light[data-row="top"]    { height: 120px; top: -60px; }     /* стена над корпусом: видно 60 px */
.room-light[data-row="bottom"] { height: 280px; bottom: -140px; } /* пол под корпусом: видно 140 px */
.room-light[data-on]:not([data-soon]) { opacity: .64; transition: opacity var(--t-on) var(--ease-out); }
.room-light[data-on="warm"]:not([data-soon]) { opacity: .4; }      /* работает, результата ещё нет: стоит, не дышит */
```

`st` — `lamps.state[r]`. Внутри `Panel` у каждого `<li>` стоит `style={{ "--i": i }}`. Через `LampTile` его не передавать: там `style` занят `lampVars`.

- `--room` = `light(hue, .5)`: `radial-gradient(closest-side, …)` с 9 ступенями затухания `FALL` (как в редакции 1), посчитанный один раз. В покое у горящей лампы пик .5 × .64 = **.32**. Пересветка при включении поднимает opacity до 1, то есть пик .5 (§5.4).
- Свет лежит в потоке страницы: прокручивается вместе с панелью и ничего не меряет. Корпус непрозрачный, поэтому видно только то, что выходит из-за его краёв. Верхний ряд (Brend…Muharrir) светит тёплым на стену над корпусом, нижний (Tarjimon…SMM) — холодным на пол. Между колонками свет проседает примерно до 12% пика, и пятна читаются раздельно.
- Блоки после `.panel-stage` рисуются поверх света. Карточки непрозрачны, текст `ink` читается на любом свете (на .32 бирюзы — 8,4:1).
- **Правило текста.** `ink-3` держит 4,5:1 только под светом ≤ .10, `ink-2` — ≤ .14 (худшая лампа Brend на графите: `ink-3` 4,52 при .10, `ink-2` 5,23 при .14). Значит, над корпусом 48 px чистого воздуха без текста, а в 140 px под корпусом нет ни `ink-2`, ни `ink-3`. Свет не приглушаем ради текста — текст отодвигаем от света.
- Под стеклом ламп `plus-lighter` не нужен: у `.lamp` стоит `isolation: isolate`, и spill смешивается только внутри своей плитки.
- Опасити меняется, градиент не перерисовывается: включение 720 мс ease-out, гашение 1000 мс ease-in, как у самой лампы.

### 4.4 Пятна за хабом (`StageLight`)

- `wash` удалить целиком.
- Пятно за мини-лампой: 200×150, `light(hue, .45)`, центр ровно под плиткой, `plus-lighter` внутри обёртки с `isolation: isolate`.
- **Пятна статичные.** `warming` → opacity .7, `on`/`you` → 1. Дыхание `spot-warm` убрать: пока пятно под стеклом дышит, `backdrop-filter: blur(24px) saturate(170%)` пересчитывается каждый кадр — весь Working и минуты рисования картинок. Дышит только сама мини-лампа над стеклом, а она бэкдроп не трогает.
- Проверка ламп хаба (`checking`) и мигание SMM (`blink`) остаются как есть: это одна секунда.
- Хаб и пятна ждут Spektr: `intro.gate` переезжает в стор (`introGate`), и `DesktopStudio` вызывает `useLamps(introGate)`. Сейчас хаб загорается раньше, чем долетят лучи.

### 5.4 Включение (вау-момент)

| t, мс | Что происходит |

## 7. Движение

Правило: **экран живёт, пока отдел работает. Когда результаты ждут владельца, движется одно — точка «ваш ход».**

| Событие | Что движется | Длительность | Сколько раз |
|---|---|---|---|
| Лампа зажглась | свечение, `lamp-on` (есть), её пятно в комнате | 720 мс ease-out | на событие |
| Лампа погасла | свечение, пятно | 1000 мс ease-in | на событие |
| Результат появился | opacity, задержка 260 мс | 360 мс | на событие |
| Включение | Spektr (есть) + пересветка пятен | ≈ 1,9 с / 0,9 с | раз на страницу |
| Взвод | уголёк → горячий филамент, шаг 70 мс | 200 мс | на смену валидности ссылки |
| Работа (`warming`) | свечение лампы .34 ↔ .70 (есть); пятна за стеклом стоят | 2,4 с | пока сотрудник работает |
| Проверка ламп хаба, мигание SMM | есть | 1,3 с / 0,9 с | раз за сессию / на одобрение |
| Ваш ход | лаймовая точка у «Postlar» 1 ↔ .45 | 4,8 с | пока посты ждут владельца |

Анимируются только `opacity` и `transform`. Цвета градиентов и раскладка не анимируются никогда.

```css

  .hub-wait { animation: none !important; }
}
@media (prefers-contrast: more) {
  .room-light, .stage-spot { display: none; }
}
@media (forced-colors: active) {
  .room-light, .stage-spot { display: none; }
  .lamp:is([data-state="on"], [data-state="you"], [data-state="warming"]) .lamp__filament { forced-color-adjust: none; background: Highlight; }
  .lamp[data-state="off"] .lamp__filament { forced-color-adjust: none; background: GrayText; }
  .lamp--xs { border: 1px solid CanvasText; }   /* мини-лампы хаба: состояние видно по филаменту */
```

## 8. Производительность и чего избегать

**Бюджет:**
- Полноэкранных слоёв света нет. Свет отдела — 10 небольших `span` в потоке страницы, меняется только opacity. При смене набора ламп перерисовки нет.
- `backdrop-filter` один (хаб), и под ним в покое ничего не движется: пятна статичны.
- `mix-blend-mode: plus-lighter` только внутри `.panel-stage` и обёртки пятен, обе изолированы.
- Пересветка, Spektr и проверка ламп — WAAPI по opacity и transform. В Chromium при CPU 4× держится ≥ 55 fps, long task > 50 мс от нашего кода нет. Если есть слабый ноутбук со встроенной графикой, проверить и на нём: CPU throttle не моделирует стоимость бэкдропа на GPU.
- Новых пакетов нет. OKLab в P0 не нужен.

**Чего избегать:**
1. Чёрных `text-shadow` и `drop-shadow` на горящей лампе в любой толщине. Плашек, подложек и скримов под текстом.
2. Сплошного `#000` и карточек темнее комнаты.
3. Света без источника: прожектора над героем, неоновых шаров, авроры, mesh-градиентов, бенто из светящихся карточек, «border beam» по кромке (Magic UI, Aceternity), прожектора за курсором.
4. Сплошной радужной полосы под карточками (свечение Apple Intelligence или Siri). Свет — отдельными пятнами у своих ламп.
5. Усреднения цветов ламп: оно даёт пыльно-лиловую дымку.
6. Дыхания под стеклом хаба, анимированного зерна, мерцания, скан-линий.
7. Текста `ink-2` и `ink-3` в зоне света (48 px над корпусом, 140 px под ним).
8. Рецепта «колба + глубокая полоса» (PR #19): владелец его отклонил.
9. Изменений телефона, `/tg` и Mini App этой ночью.
10. Лайма в любом свете, пятне или свечении.

**Сравнить рядом с higgsfield.ai** до показа владельцу. По памяти рецензента, у Higgsfield похожий жёлто-зелёный акцент на чёрном. Лайм — решение владельца о бренде, и сегодня его не меняем. Но если пара «лаймовая пилюля на тёмном + стеклянный сайдбар» читается как Higgsfield, сказать об этом владельцу отдельным вопросом. Графит вместо чёрного и тёплые лампы уже уводят от этой картинки.

### 9.2 Метрики (автоматически, каждый кадр ПК)

`studio-ux-screens/atmo/metrics.py` (PIL + numpy, запуск `python -I metrics.py <png>…`): доля чистого чёрного, доля тёмного, средняя OKLab L, доля цвета (C ≥ 0,04 и L ≥ 0,35). Определения — как в §1.1. Им же посчитана таблица §1.1.

| Кадр | Чистый чёрный | Тёмное (≤ 20) | Средняя L | Цвет |
|---|---|---|---|---|
| любой кадр ПК | ≤ 1% | ≤ 35% | — | — |
| Working (3–4 лампы), Postlar с картинкой | — | — | ≥ 0,23 | ≥ 5% |
| Bo‘lim, лендинг в покое | — | — | ≥ 0,23 | ≥ 8% |
| Start в покое, Postlar без картинок | — | — | ≥ 0,20 | угольки: у каждого ≥ 40 px с C ≥ 0,06 |

Долю цвета смена токена не даёт, её дают только горящие лампы, их свет и картинки. Поэтому именно этот столбец ловит «по-прежнему безжизненно». Было: Start 0,4%, Working 0,3%, образец Postlar 1,6%.

## 10. P1 и P2

**P1 (после P0, если есть время, или завтра):**
- **Свет картинки поста** в превью Postlar Pro. Обёртка в `Posts.tsx`, а не `PostImage`. Картинка → canvas 4×4 → берём **самый хроматичный** из 16 сэмплов. Если его хрома < 0,04 — свечения нет (белый мрамор не даст серую дымку). Ограничения: L .5–.6, C ≤ .12, оттенок дальше 28° от лайма, альфа ≤ .18. `img.onerror` (у `*.fal.media` может не быть CORS) → свечения нет, палитру бренда вместо картинки не подставляем. Для jpg образца цвета посчитать заранее и записать в `sample.ts`.
- **Свет вывески** на верх холста, когда есть измеренные цифры: отдельная обёртка с opacity под `ChannelSign`, не фон `main`. Пока «o‘lchanmoqda…» — света нет.
- **Зерно:** статичный PNG 256×256 ≤ 10 КБ (PIL), opacity .04, без `mix-blend-mode`. Только если в точке A графит выглядит плоским.
- **Телефон и Mini App:** та же логика (текст под колбой, без ореолов). Но плитки 74 px придётся растить, а это ломает «панель и Spektr в первом экране». Сначала показать владельцу один кадр 375, потом согласовать с сессией `miniapp`.
- Шапка `LampDrawer` (`.lamp-head-ink` с тенью `rgb(0 0 0/.35)` 10 px): проверить, не читается ли она как обводка.
- Kanal Pro: план недели — плитки с картинками там, где пост с картинкой есть.

**P2:** палитра клиента (её нечем применять без дежурного света); выравнивание светлоты десяти оттенков в OKLCH (меняет фирменные hex и Spektr); перфорированная стена, проявляемая светом (флаг `?dots=1`, только с вопросом владельцу); параллакс при прокрутке.
